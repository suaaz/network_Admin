Module 01

OSI 7-Layer vs TCP/IP & Architecture

The 7-Layer OSI Reference Model & PDU Encapsulation

The Open Systems Interconnection (OSI) model standardizes network communication into 7 distinct abstraction layers. As data moves down the stack from sender to receiver, each layer prepends its own Protocol Data Unit (PDU) header (encapsulation). At the receiving end, each layer strips its corresponding header (de-encapsulation).

Layer Name PDU Core Function & Addressing Hardware / Protocols
Layer 7 Application Data Direct interface to user software; high-level APIs. HTTP/S, DNS, DHCP, SSH, BGP, SNMP
Layer 6 Presentation Data Data formatting, serialization, encryption & compression. TLS/SSL, ASCII, UTF-8, JSON, JPEG
Layer 5 Session Data Establishes, maintains, and synchronizes dialogues between apps. NetBIOS, RPC, Sockets, PPTP
Layer 4 Transport Segment / Datagram End-to-end reliability, flow control (sliding window), port addressing. TCP, UDP, SCTP, QUIC (Ports 1-65535)
Layer 3 Network Packet Logical addressing, path determination across subnets, fragmentation. Routers, L3 Switches, IPv4, IPv6, ICMP, IPsec
Layer 2 Data Link Frame Physical node-to-node transfer, MAC addressing, collision/error check (CRC). L2 Switches, Bridges, Ethernet 802.3, ARP, VLANs
Layer 1 Physical Bits Electrical, optical, or radio transmission of raw bits on wire/air. Cables (Cat6, Fiber SFP+), Hubs, Modems, RJ45

Interactive Encapsulation Pipeline (Sender Stack)

L7-L5 Application Payload (HTTP Data)
L4 Header Src Port: 54120 | Dst Port: 443 | Seq / Ack | Window Size + [ Payload ]
L3 Header Src IP: 192.168.1.50 | Dst IP: 142.250.190.46 | TTL: 64 | Proto: 6 (TCP) + [ TCP Segment ]
L2 Header Dst MAC: Gateway MAC | Src MAC: Client NIC | EtherType: 0x0800 (IPv4) + [ Packet ] + [ FCS CRC 4-Bytes ]
L1 Bits 01001000 01100101 01101100 01101100 01101111 (Physical wire voltages / optical pulses)

Physical & Logical Network Topologies

Star Topology (Standard LAN)

All edge hosts connect directly to a central switch. Single cable failure only disconnects that node. Central switch is single point of failure (mitigated via dual-homed LACP).

Dominant in modern enterprise access layers.
Mesh Topology (WAN / Core)

Every node connects to every other node ($N \times (N-1) / 2$ links). Maximum redundancy and zero single point of failure. Expensive; Partial Mesh is used for practical enterprise WANs.

Used in ISP backbones & mission-critical sites.
Spine-and-Leaf (Modern DC)

Every Leaf switch connects to every Spine switch. No leaf-to-leaf or spine-to-spine links. Every server is exactly 2 hops away from any other server, enabling ultra-low predictable East-West latency.

Standard for hyperscale & cloud datacenters.

RFC 1918 Private Addressing & Special Purpose Blocks

RFC 1918 sets aside three non-routable address ranges for internal private enterprise networks. These addresses cannot be routed across the public Internet and require Network Address Translation (NAT) to access Internet resources.

10.0.0.0 /8
10.0.0.0 — 10.255.255.255
16,777,216 addresses (Class A). Default for enterprise campuses & cloud VPCs.
172.16.0.0 /12
172.16.0.0 — 172.31.255.255
1,048,576 addresses (16 contiguous /16 blocks). Common for DMZs & VPN pools.
192.168.0.0 /16
192.168.0.0 — 192.168.255.255
65,536 addresses (256 contiguous /24 blocks). Ubiquitous in SOHO & branch offices.
Special Purpose IPv4 Ranges Every Admin Must Know:
  • 127.0.0.0/8 (Loopback): Localhost software loopback interface (127.0.0.1). Packets never leave the local host NIC.
  • 169.254.0.0/16 (APIPA): Automatic Private IP Addressing. Assigned by OS when DHCP server fails to respond. If you see this, DHCP is down or blocked!
  • 224.0.0.0/4 (Multicast): Class D range (e.g., 224.0.0.5 for OSPF All Routers, 224.0.0.102 for HSRP).
  • 0.0.0.0/0 (Default Route): "Gateway of Last Resort" representing all unknown destinations.

IPv6 Architecture & Address Notation

IPv6 uses 128-bit addresses (represented as 8 groups of 4 hexadecimal digits separated by colons, e.g., 2001:0db8:85a3:0000:0000:8a2e:0370:7334). Providing $3.4 \times 10^{38}$ unique addresses, it eliminates the need for NAT and broadcast addresses (using multicast instead).

Compression Rules:
  • Omit Leading Zeros: :0042: becomes :42:.
  • Double Colon (::): Replace one contiguous sequence of all-zero 16-bit blocks with :: (can only be used once per address!).
  • Example: fe80:0000:0000:0000:0202:b3ff:fe1e:8329 compresses to fe80::202:b3ff:fe1e:8329.
Key Address Scopes:
  • 2000::/3 — Global Unicast (Public Internet routable)
  • fe80::/10 — Link-Local (Automatic for single link communication)
  • fc00::/7 — Unique Local (ULA, IPv6 equivalent of RFC 1918)
  • ff00::/8 — Multicast (Replaces all IPv4 broadcasts)
  • ::1/128 — Loopback (Equivalent to 127.0.0.1)
Module 03

Switching, VLANs & Spanning Tree (STP)

How Layer 2 Switches Operate: Learning, Flooding, Forwarding

Layer 2 switches maintain a Content Addressable Memory (CAM) table that binds physical switch ports to known MAC addresses. Switch logic operates on four fundamental rules:

1. Learning

Inspects the Source MAC on incoming frame. If not present in CAM table, records [Port + MAC + VLAN + Timer].

2. Flooding

If the Destination MAC is unknown or is a broadcast (FF:FF:FF:FF:FF:FF), switch forwards out ALL ports in the VLAN except the ingress port.

3. Forwarding / Filtering

If Destination MAC is found in CAM table on a different port, switch unicast forwards it directly out that port. If on same port, it drops (filters) it.

4. Aging

CAM entries expire after an aging timer (default: 300 seconds) if no new frames arrive from that Source MAC, freeing memory.

Virtual LANs (VLANs) & IEEE 802.1Q Frame Tagging

A VLAN logically divides a single physical switch into multiple isolated broadcast domains. Traffic between different VLANs cannot cross Layer 2; it requires a Layer 3 routing device (Router-on-a-Stick or Layer 3 Switch SVI).

802.1Q 4-Byte Tag Insertion Anatomy
Src & Dst MAC 12 Bytes
TPID (0x8100) 16 Bits (2 Bytes) Identifies 802.1Q Frame
TCI (PCP + DEI + VID) 16 Bits (2 Bytes) 12-Bit VID (0 - 4095)
EtherType & Payload 46 - 1500 Bytes
Access Port: Belongs to 1 VLAN; strips 802.1Q tag when forwarding to end-host PC. Trunk Port: Carries multiple VLANs between switches with 802.1Q tags intact. Native VLAN: Untagged traffic crossing a trunk (default: VLAN 1).

Spanning Tree Protocol (STP 802.1D & RSTP 802.1w)

Redundant physical connections between switches cause Layer 2 broadcast storms, duplicate frames, and MAC table flapping because Ethernet frames lack a TTL field. STP solves this by electing a Root Bridge and logically blocking redundant links.

1. Root Bridge Election

The switch with the lowest Bridge ID (BID) wins. BID = Priority (default 32768) + SysID Ext (VLAN ID) + Base MAC Address.

spanning-tree vlan 10 priority 4096
2. Port Roles
  • Root Port (RP): Lowest cost path to Root Bridge (1 per non-root switch).
  • Designated Port (DP): Best port on a segment (forwards traffic).
  • Alternate / Blocked: Discards frames to eliminate loop.
3. RSTP Port States
Discarding: Drops user frames, listens for BPDUs.
Learning: Learns MACs into CAM, drops user frames.
Forwarding: Fully operational data forwarding.
Module 04

Routing Architecture, OSPF & BGP

Routing Table Hierarchy & Longest Prefix Match

When a router forwards an IP packet, it always prioritizes the Longest Prefix Match (most specific subnet mask) regardless of Administrative Distance. Only when prefix lengths are identical does it compare Administrative Distance (AD).

Route Source Administrative Distance (AD) Default Metric Category
Connected Interface00Hardware Direct
Static Route10Manual Config
eBGP (External BGP)20AS-Path, Weight, etc.Exterior Gateway
EIGRP (Internal)90Bandwidth + DelayAdvanced Distance Vector
OSPF110Cost = 10^8 / BandwidthLink-State
iBGP (Internal BGP)200AttributesExterior Gateway within AS

OSPF (Open Shortest Path First) & Area Hierarchy

OSPF is an open-standard Link-State Interior Gateway Protocol (IGP) that uses Dijkstra's Shortest Path First (SPF) algorithm. Every router in an area builds a full Link-State Database (LSDB) representing the entire network topology.

OSPF Neighbor State Machine:
  1. Down: No Hello packets received yet.
  2. Init: Hello received, but local Router ID not seen in neighbor list.
  3. 2-Way: Bi-directional communication achieved. DR/BDR elected.
  4. ExStart: Master/Slave election for sequence numbering.
  5. Exchange: Routers exchange Database Description (DBD) packets.
  6. Loading: Routers request missing LSAs using LSR & LSU packets.
  7. Full: Databases fully synchronized; shortest path computed.
Areas & Router Roles:
  • Backbone Area 0: Central core of all OSPF topologies. All non-zero areas must connect directly to Area 0.
  • Area Border Router (ABR): Sits on the boundary between Area 0 and another area; summarizes routes.
  • Autonomous System Boundary Router (ASBR): Connects OSPF to external routing domains (e.g., BGP or static routes).
  • DR / BDR: Designated Router & Backup DR reduce link-state flooding on multi-access Ethernet segments (uses multicast 224.0.0.5 & 224.0.0.6).

BGP Path Selection & Autonomous Systems

BGP is the routing protocol that powers the global Internet. Operating over TCP port 179, it uses Path-Vector logic and granular policy attributes rather than raw speed metrics to choose the best path between Autonomous Systems (ASNs).

BGP Best Path Decision Algorithm (Strict Order):
1. Weight (Highest, Cisco proprietary local)
2. LOCAL_PREF (Highest, standard across AS)
3. Locally Originated (network/aggregate cmd)
4. AS_PATH (Shortest autonomous system hops)
5. Origin Code (IGP < EGP < Incomplete)
6. MED (Lowest Multi-Exit Discriminator)
7. Neighbor Type (eBGP over iBGP)
8. Lowest IGP Cost to BGP next-hop
9. Lowest BGP Router ID (Tie-breaker)
Module 05

Core Network Services (DNS, DHCP, NAT & Telemetry)

Domain Name System (DNS) Hierarchical Resolution

DNS translates human-readable hostnames (api.example.com) into IP addresses. It uses a distributed, hierarchical database starting from Root servers down to Authoritative Name Servers.

A IPv4 Address mapping
AAAA IPv6 Address mapping
CNAME Canonical alias to another domain
MX Mail Exchange destination server
TXT Text records (SPF, DKIM, DMARC)
PTR Reverse DNS (IP to hostname)

Dynamic Host Configuration Protocol (DHCP) & DORA

DHCP automates IP assignment, default gateway configuration, DNS servers, and lease management using UDP ports 67 (Server) and 68 (Client).

1. DISCOVER
Client broadcasts (255.255.255.255) searching for available DHCP servers.
2. OFFER
Server reserves an IP from pool and offers it to client's MAC address.
3. REQUEST
Client broadcasts accepting the chosen server's offer and declines other offers.
4. ACKNOWLEDGE
Server confirms lease terms, DNS servers, gateway, and subnet mask.
DHCP Relay (ip helper-address): Routers block broadcasts by default. When clients and DHCP servers sit on different VLANs/subnets, the router interface requires ip helper-address <DHCP-Server-IP> to convert the Layer 2 broadcast into a unicast packet forwarded directly to the DHCP server.

NAT & PAT (Port Address Translation / Overload)

Inside Local

The private IP address assigned to an internal host on the inside network (e.g. 192.168.1.50).

Inside Global

The registered public IP address that represents the inside host to the outside world (e.g. 203.0.113.1).

Outside Local

The IP address of an outside host as it appears to the inside network (usually identical to Outside Global).

Outside Global

The actual public IP address assigned to an external host on the Internet (e.g. 198.51.100.25).

Module 06

Network Security, ACLs & IPsec VPNs

Firewalls & Access Control Lists (Standard vs Extended)

Standard ACLs (1-99 & 1300-1999)
  • • Filters based ONLY on Source IP address.
  • • Cannot inspect protocols, TCP/UDP ports, or destinations.
  • • Best Practice: Place Standard ACLs as close to the DESTINATION as possible so valid traffic isn't dropped prematurely elsewhere.
access-list 10 permit 192.168.1.0 0.0.0.255
Extended ACLs (100-199 & 2000-2699)
  • • Filters on Source IP, Destination IP, Protocol (TCP/UDP/ICMP), and Port numbers.
  • • Supports state tracking options (established).
  • • Best Practice: Place Extended ACLs as close to the SOURCE as possible to save router CPU and network bandwidth.
access-list 101 permit tcp 192.168.1.0 0.0.0.255 any eq 443
CRITICAL RULE: Every ACL has an invisible deny any any (implicit deny) at the very bottom. If incoming packets don't match any permit rule above, they are silently dropped!

Site-to-Site IPsec VPN Architecture (IKE Ph1 & Ph2)

IPsec provides confidentiality, integrity, authentication, and anti-replay protection across insecure public networks through a two-phase negotiation.

IKE Phase 1 (ISAKMP SA)

Negotiates a secure encrypted control channel between the two gateway routers.

  • • HAGLE: Hash (SHA-256), Authentication (Pre-Shared Key / RSA), DH Group (Diffie-Hellman Group 14/19/21), Lifetime (86400s), Encryption (AES-GCM-256).
  • • Port: UDP 500 (UDP 4500 if NAT Traversal is detected).
IKE Phase 2 (IPsec SA / Transform Set)

Negotiates the actual encrypted data tunnel parameters used to protect user traffic.

  • • ESP (Protocol 50): Encapsulating Security Payload (Provides both encryption & integrity).
  • • AH (Protocol 51): Authentication Header (Integrity only; cannot pass through NAT).
  • • Mode: Tunnel Mode (encapsulates entire original IP packet).

Module 08

Spine-Leaf, VXLAN & Cloud Architecture

Clos Spine-and-Leaf & Network Overlays (VXLAN / EVPN)

Spine-and-Leaf Clos Fabric:
  • • Eliminates traditional Spanning Tree blocking in modern datacenters.
  • • All links forward simultaneously using Layer 3 ECMP (Equal-Cost Multi-Path).
  • • Predictable latency: exactly 2 hops between any pair of servers.
  • • High scalability: add Spine switches to expand bandwidth, add Leaf switches to expand server ports.
VXLAN (RFC 7348) & EVPN:
  • • Encapsulates Layer 2 Ethernet frames inside Layer 3 UDP packets (port 4789).
  • • Expands VLAN limit from 4,096 to 16 million Virtual Network Identifiers (VNIs).
  • • Decouples virtual workloads (Overlay) from the physical routing network (Underlay).
  • • BGP EVPN serves as the modern control plane for MAC/IP route distribution.
